# TEST visual system — Patch-inspired reference

This document analyzes the public visual language of The Patch System as design input only. It does not copy that site's assets, copy, illustrations, brand marks, or proprietary implementation.

## Design character

The reference uses a deliberately high-impact contrast: electric saturated hero stages, warm off-white editorial surfaces, oversized condensed display headlines, small mono labels, orange action controls, visible grids, and large section numerals. The effect feels like a designed system rather than a generic product template.

For TEST, these principles become a signal/index/allocation visual language. They do not inherit the source site's healthcare or marketing story.

## Typography

- Heavy geometric display type for compact uppercase headlines, set with tight tracking.
- Mono type only for labels, numerals, buttons, and navigation; positive tracking.
- Regular sans body copy at 16–18px in short paragraphs.
- Deliberate line breaks create editorial rhythm; body copy never carries the display style.

## Layout primitives

1. Electric-grid hero: full-width blue panel with a CSS grid, nav inside the stage, and a large left-aligned statement.
2. Editorial index card: paper card over the hero with a large figure, status pill, and progress rail.
3. Numbered sections: use 01, 02, 03 as wayfinding before every major declaration.
4. Rule-based cards: 1–2px borders, tight radius, no soft shadows.
5. Kinetic texture: use independent canvas particles, SVG curves, grids, and bands; never reuse source imagery.
6. Alternating polarity: blue technical stage, paper data stage, dark explanation stage, warm reward stage.

## Motion

- Hero canvas uses low-density particles and orbit lines with restrained pointer parallax.
- Grid remains static and anchors the composition.
- HTML always contains the information; canvas is decorative.
- Reduced-motion users receive the static grid without animation.

## Guardrails

- Do not imitate the source site's copy, logo, imagery, client claims, or service narrative.
- Do not use medical, patient, revenue, or testimonial language from the source.
- Do not frame TEST as a guaranteed financial outcome.
- Keep the remaining 750M explicitly unassigned until a policy is published.
